# Internationalization (i18n) Guidelines

> **Library:** `next-intl`  
> **Dictionaries:** `dictionaries/*.json` (default: `dictionaries/en.json`)  
> **Type Safety:** `global.d.ts` via `AppConfig` module augmentation

---

## Core Rule: Always Use Translations

**Never hardcode user-facing copy in pages, components, forms, or error messages.**

Every user-facing string—including titles, descriptions, placeholders, button labels, and error messages—must be defined in the dictionary files and referenced via `next-intl`.

---

## Dictionary Structure

- Store dictionary files in `dictionaries/{locale}.json` (e.g. `dictionaries/en.json`).
- Structure keys hierarchically by page or feature namespace:

```json
{
  "HomePage": {
    "title": "Buttler"
  },
  "LoginPage": {
    "title": "Sign in to Buttler",
    "description": "Authenticate with your GitHub account to continue.",
    "continueWithGitHub": "Continue with GitHub",
    "errors": {
      "github": "GitHub authentication failed. Please try again."
    }
  }
}
```

---

## Usage in Server Components

In Server Components (layouts, pages), always use `getTranslations` from `next-intl/server`:

```tsx
import { getTranslations } from "next-intl/server";

const Page = async () => {
  const t = await getTranslations("HomePage");

  return <h1>{t("title")}</h1>;
};
```

---

## Usage in Client Components

For Client Components (`"use client"`), provide client messages through `NextIntlClientProvider` in `app/[locale]/layout.tsx` using `pick` from `@omer/object`:

```tsx
// app/[locale]/layout.tsx
import { pick } from "@omer/object";
import { NextIntlClientProvider } from "next-intl";
import { getLocale, getMessages } from "next-intl/server";

export default async function({ children }: LayoutProps<"/[locale]">) {
  const [locale, messages] = await Promise.all([
    getLocale(),
    getMessages(),
  ]);

  return (
    <html lang={locale}>
      <body>
        <NextIntlClientProvider
          messages={pick(
            messages,
            "NewServicePage",
          )}
        >
          {children}
        </NextIntlClientProvider>
      </body>
    </html>
  );
}
```

Then in the Client Component, access translations directly via `useTranslations`:

```tsx
// Client Component (e.g. NewServiceForm.tsx)
"use client";
import { useTranslations } from "next-intl";

const NewServiceForm = () => {
  const t = useTranslations("NewServicePage");

  return <h2>{t("title")}</h2>;
};
```


---

## Type Safety

The project uses `global.d.ts` to augment `next-intl`'s `AppConfig.Messages` with the schema of `dictionaries/en.json` and `AppConfig.Locale` with `routing.locales`.

- All `t(...)` keys are strictly type-checked at compile time.
- Both `getLocale()` and `useLocale()` already return a typed locale (`AppLocale`). Do not use redundant type assertions like `locale as AppLocale`.

```bash
npx tsc --noEmit
```
